# 0014: Pre-1.0 compatibility policy

Date: 2026-07-24
Status: accepted

## Context

v0.1.0 is published — npm (`@ncukondo/gdrive-cli`) and GitHub Releases with
binaries and a self-upgrade path. Published is not the same as adopted: there
are **no known users** yet, and no downstream automation depends on this CLI.

[0007](0007-output-and-errors.md) declares the JSON envelope, `error.code`
values, and each command's `data` fields "a contract — additive changes
preferred, breaking changes require a decision record". That is the right
long-run posture for an agent-facing tool, but applied literally today it makes
us pay a compatibility tax on behalf of users who do not exist, and locks in
shapes that were designed without a single real integration to learn from.

This record scopes that contract to the period where it earns its keep.

## Decision

While the version is **0.x** and there is no known user, breaking changes to
the CLI's inputs and outputs are **allowed in a minor release** without a
deprecation period:

- command and subcommand names, arguments, flags, and defaults
- JSON `data` field names, shapes, and nesting (and the envelope itself)
- text and quiet output
- `error.code` values and the exit-code mapping
- the config file schema and the on-disk token/credential layout

Each such change still must:

1. update `docs/` and the affected `decisions/` record in the same commit —
   the decisions stay the source of truth for *why*, so a superseded one is
   edited or marked `superseded by NNNN`, never silently contradicted;
2. be called out in the release notes for the version that ships it;
3. bump the **minor** version (0.x.0), never just the patch.

Deliberately *not* covered by this licence, because they cost a user real
trouble even when there is only one of them:

- silently changing where credentials live, or leaving a stale token file that
  still looks valid. A move must migrate or fail loudly with a fix to run.
- widening OAuth scopes without saying so; that needs a re-consent and belongs
  in [0005](0005-auth-and-scopes.md).

### When this ends

This record is superseded the moment either becomes true:

- **1.0.0 is released**, or
- **a user is known** — an issue, a dependent package, or a request to keep
  something stable.

From then on 0007's contract applies as written: additive changes preferred,
breaking changes need a major bump and a deprecation path. Whoever notices the
trigger writes the superseding record; do not let 0.x drift past it by default.

## Consequences

- 0007's stability language should be read as "from 1.0", not "from now".
- Refactors that would otherwise be deferred for compatibility reasons — a
  reshaped `data` payload, a renamed flag, a different config key — are cheap
  right now, and this is the window to make them. Task
  [0015](../tasks/0015-googleapis-upgrade.md) explicitly defers replacing the
  `as unknown as` client casts partly on churn grounds; that trade-off is
  softer while this record stands.
- The release notes become the compatibility record for 0.x, so they have to
  actually list breaking changes rather than lean on `--generate-notes` alone.
- Being pre-1.0 licenses breaking changes, not careless ones: the bar is still
  that the new shape is better, not merely different.
