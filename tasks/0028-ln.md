# Task 0028: `gdrive ln` creates a shortcut

Status: todo (move to `tasks/archive/` when done)
Depends on: 0027 — needs `resolveTarget`, the `shortcut` `FileType`, and the
`target_id` / `target_type` fields that 0027 adds.
Parallel: no — 0027 is the only thing it waits for, but it edits `lib/api.ts`
and `commands/drive-write.ts`, which 0027 also touches.

## Goal

`gdrive ln <target> <folder> [--name <name>]` creates a Drive shortcut in
`<folder>` pointing at `<target>`, named after the target unless `--name` says
otherwise.

## Context

- Decision: [`0026`](../decisions/0026-ln.md). It extends
  [`0025`](../decisions/0025-shortcuts.md), whose §1 role table governs both
  arguments — do not invent a third rule here.
- Also relevant: [`0008`](../decisions/0008-drive-commands.md) (the file object
  and the command table), [`0015`](../decisions/0015-no-type-assertions.md)
  (`GeneratedParamChecks` for the new request body field),
  [`0013`](../decisions/0013-architecture.md) (command registration contract).
- Docs: `docs/commands.md`, `README.md`.
- The create call is `files.create` with
  `mimeType: "application/vnd.google-apps.shortcut"`,
  `parents: [folderId]`, `shortcutDetails: { targetId }`,
  `supportsAllDrives: true`, `fields: FILE_FIELDS`.

## Scope

- `src/lib/api.ts` — `FileCreateBody` gains `shortcutDetails`; a
  `createShortcut` wrapper beside `copyFile`.
- `src/commands/ln.ts` + `src/commands/ln.test.ts` — new.
- `src/commands/drive-write.ts` — register `ln`, wiring `<target>` and
  `<folder>` to `resolveTarget`.
- `src/commands/file-format.ts` — only if the `->` text line needs a helper;
  prefer keeping it in `ln.ts`.

## Out of scope

- Retargeting, `--force`, and `resourceKey` — all deferred in 0026.
- Any change to how existing commands treat shortcuts; that is 0027.

## TDD plan

1. **The API wrapper** (`lib/api.ts`)
   - **Red** — `createShortcut(client, targetId, parentId, name)` sends the
     shortcut MIME, the parent, `shortcutDetails.targetId`, the name, and
     `supportsAllDrives: true`; the normalized result carries `type: "shortcut"`
     with `target_id`. A Drive 403 still maps to `PERMISSION_DENIED`
     ([0017](../decisions/0017-permission-denied-error-code.md)) rather than
     being swallowed.
   - **Green** — extend `FileCreateBody`, add the wrapper, keep the
     `GeneratedParamChecks` entry compiling.
   - **Refactor** — share the create path with the existing `files.create`
     callers only if it stays one obvious function; do not merge otherwise.

2. **The command** (`commands/ln.ts`)
   - **Red** —
     - with `--name`, creates a shortcut of that name and never fetches the
       target's metadata;
     - without `--name` and with an id target, uses the `file` `resolveTarget`
       already returned and issues no extra `files.get` (assert the call count
       — this is 0026 §3's claim);
     - without `--name` and with a path target, fetches the target once and uses
       its name;
     - `<target>` that is a shortcut resolves to *its* target, so the created
       shortcut's `target_id` is the document, not the shortcut (0026 §2);
     - `<folder>` that is a shortcut to a folder creates inside the target
       folder;
     - text output names both ends; JSON `data.file` carries `target_id` and
       `target_type`; quiet is the new shortcut's id;
     - a Drive refusal (cross-drive placement) surfaces its message rather than
       a generic one.
   - **Green** — implement the handler and `createLnCommand`.
   - **Refactor** — the "name it after the target" branch is the only place that
     may fetch; keep it a single expression, not a flag threaded through.

3. **Registration and docs**
   - **Red** — `drive-write.ts` registers `ln`; `gdrive ln --help` lists
     `--name`.
   - **Green** — register it.
   - **Docs** — `docs/commands.md` gains an `ln` section next to `mv`/`cp`, and
     the shortcuts section from 0027 links to it as the way to make one.
     `README.md`'s Drive highlight line gains `ln`.

## Acceptance criteria

- [ ] `docs/commands.md` and `README.md` updated
